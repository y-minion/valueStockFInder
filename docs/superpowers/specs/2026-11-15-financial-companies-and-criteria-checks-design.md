# 금융회사 포함과 기준 점검 설계

- 날짜: 2026-11-15
- 바탕 문서: `docs/superpowers/specs/2026-11-14-weekly-dividend-screener-design.md` (아래에서 '원래 설계')
- 이 문서에는 원래 설계에서 바뀌거나 더해지는 부분만 적어요. 여기 없는 부분은 원래 설계를 그대로 따라요.
- 원래 설계의 '하지 않을 것' 중 "금융회사 분석"은 이 문서로 바뀌어요. 리츠·스팩·우선주·ETF/ETN 제외는 그대로예요.

## 1. 왜 하나

- 사용자는 ISA로 배당주에 오래 투자해요. 한국 배당주에는 은행·금융지주·보험이 많아요. KB금융, 신한지주, 삼성화재 같은 회사예요.
- 원래 설계는 금융회사를 뺐어요. 계산기의 관문 ① 기준이 금융회사에 맞지 않아서예요.
  - 부채비율: 은행은 예금이 부채라 1,000%를 넘어요. KB금융 2025년이 약 1,250%예요.
  - 영업현금흐름: 대출과 예금 흐름이 섞여요. 삼성증권 2025년이 −5.3조예요.
  - 이자보상배율: 이자가 은행 장사의 원가라서 뜻이 없어요.
- 사용자 말: "금융 회사도 올바른 기준만 된다면 포함해도 좋을 것 같은데".
- 사용자는 기준값을 스스로 정하는 게 믿을 만한지도 물었어요. 그래서 이렇게 하기로 했어요(2026-11-15 합의).
  - 기준은 실습 가이드 기본값으로 둬요. 계산기 '기준값' 시트에 근거가 적혀 있어요.
  - 기준이 얼마나 걸러 내는지 데이터로 점검해요. 이것이 '기준 점검표'예요.
  - 기준 바로 근처의 종목은 따로 표시해요. 이것이 '경계 표시'예요.
  - 공식 기준이 있는 숫자는 공식 기준을 기본값으로 써요. 금융회사 자본비율이 그 예예요.

## 2. 목표, 하지 않을 것, 실패

**목표**
1. 은행, 금융지주, 보험, 증권, 카드·캐피탈을 금융업에 맞는 기준으로 분석해요.
2. 기준 바로 근처에 있는 종목을 '경계'로 보여줘요.
3. 시장 전체를 돌린 실행에서, 기준마다 몇 %가 통과하는지와 기준을 한 칸 움직이면 무엇이 바뀌는지 보여줘요.

**하지 않을 것**
- 리츠, 스팩, 우선주, 신탁·집합투자(인프라펀드 등)는 지금처럼 빼요.
- 원본 계산기 엑셀은 바꾸지 않아요. 금융회사용 엑셀 시트를 새로 만들지도 않아요.
- 기준을 데이터로 자동 조정하지 않아요. 점검표는 보여주기만 하고, 기준은 사용자가 바꿔요.
- 경계 표시는 판정을 바꾸지 않아요.

**실패로 보는 것**
- 금융회사가 일반 기준(부채비율 등) 때문에 조용히 탈락하는 것.
- 자본비율을 모르는데 통과처럼 보이는 것. 모르면 '직접 확인'이어야 해요.
- 일반 회사의 판정이나, 일반 회사의 엑셀·리포트 판정 일치가 깨지는 것.

## 3. 금융회사

### 3.1 대상과 종류

DART 기업개황의 업종코드(한국표준산업분류)로 나눠요. 아래 예의 업종코드는 2026-11-15에 실제 DART 응답에서 확인했어요.

| 종류 | 알아보는 법 | 예 |
|---|---|---|
| 금융지주 | 지주회사(64992)이면서 최근 재무상태표에 유동자산 줄이 없음 (지금 규칙 그대로) | KB금융, 신한지주, 하나금융지주, 우리금융지주 (64992) |
| 은행 | 업종코드가 6412로 시작 (일반은행. 저축은행 등 나머지 641은 '그 밖의 금융') | 기업은행, 카카오뱅크 (64121) |
| 보험 | 651 또는 652로 시작 | 삼성생명 (65110), 삼성화재·DB손해보험 (65121) |
| 증권 | 6612로 시작 | 삼성증권 (66121) |
| 카드·캐피탈 | 6491로 시작 (빌더가 삼성카드 등 실제 코드로 확인) | |
| 그 밖의 금융 | 위에 없는 64·65·66 | 맥쿼리인프라 (64201) |

- '그 밖의 금융'은 지금처럼 빼고, 제외 사유는 "금융회사(그 밖)"으로 적어요.
- LG처럼 유동자산 줄이 있는 지주회사는 지금처럼 일반 회사예요.
- `settings.toml`의 `[financial] include`가 기본 `true`예요. `false`로 두면 지금처럼 금융회사를 모두 빼요.

### 3.2 숫자

- 아래 숫자는 DART에서 일반 회사와 똑같이 받아요. 기능 시험에서 KB금융, 삼성화재, 삼성증권 2025년 자료로 읽히는 것을 확인했어요.
  - EPS, DPS, ROE, 지배주주 순이익, 배당금 지급 총액
- 금융회사에 뜻이 없는 숫자는 비워요. 리포트에는 '해당 없음'으로 보여요.
  - 부채비율, 이자보상배율, 영업현금흐름, 설비투자
- 가격 쪽(관문 ③)은 일반 회사와 같아요. PER, PBR, 적정가 A·B·C, 매수선이에요.

### 3.3 관문 판정 (금융업 기준)

**관문 ① 좋은 회사인가**

| 항목 | 기준 | 비고 |
|---|---|---|
| ROE 5년 평균 | `criteria.roe_min` 이상 (기본 8%) | 일반 회사와 같은 값이에요. 업종 덮어쓰기도 그대로 적용돼요 |
| 최근 5년 적자 없음 | 지배주주 순이익이 5년 모두 0보다 큼 | 새 항목이에요. 순이익이 빈 해가 있으면 '입력 필요' |
| 자본비율 | 종류별 최소값 이상 (3.5) | FISIS 키가 없거나 값을 못 받으면 '직접 확인' |
| 부채비율, 이자보상배율, 영업현금흐름÷순이익 | 해당 없음 | |
| 업종 비교 (켰을 때) | 지금과 같아요 | |

결과는 지금 규칙과 같아요. 탈락이 하나라도 있으면 '탈락'이에요. '입력 필요'나 '직접 확인'이 있으면 '확인 필요'이고, 아니면 '통과'예요.

**관문 ② 배당이 오래 갈까**

| 항목 | 기준 |
|---|---|
| 배당을 거른 해 | 0번 (그대로) |
| 배당을 줄인 해 | 0번, 아니면 직접 확인 (그대로) |
| 배당성향 평균 | 20~60% (그대로) |
| 잉여현금흐름÷배당 | 해당 없음 |

**관문 ③·④**는 그대로예요.

- 상태(매수선 이하, 관심, 탈락), 변화 감지, 첫 페이지 숫자는 모두 이 판정을 써요.
- 구현 방향: 엑셀과 똑같이 계산하는 부분(`engine.compute`)은 그대로 둬요. 금융회사일 때만 그 결과에 금융업 판정을 덧씌워요. 업종 비교를 붙인 자리와 같은 곳이에요.
- 그래서 금융회사만 엑셀 수식의 판정과 리포트 판정이 다를 수 있어요. 3.7에서 다뤄요.

### 3.4 자본비율 (선택: 금감원 FISIS 키)

**받을 곳**
- 금감원 금융통계정보시스템(FISIS) OPEN API예요.
- 주소는 `https://fisis.fss.or.kr/openapi/` 아래의 `companySearch`, `statisticsListSearch`, `accountListSearch`, `statisticsInfoSearch`예요.
- 키는 `keys.toml`의 `[fisis] auth_key`에 넣어요. 선택이고, 32자리예요.

**키가 없을 때**
- 자본비율 칸은 '직접 확인'이에요.
- 카드에 어디서 보는지 안내해요. FISIS 사이트나 사업보고서의 '자본적정성' 부분이에요.
- 이때 관문 ①은 많아야 '확인 필요'예요. 탈락하지 않으니 관심 목록에는 오를 수 있어요.

**키가 있을 때**
- 종류마다 가장 최근 분기 값 하나를 받아 기준과 비교해요. 그 기준월을 출처 글에 적어요.

| 종류 | FISIS 권역 코드 | 지표 |
|---|---|---|
| 금융지주 | L | 보통주자본비율 |
| 은행 | A | 보통주자본비율 |
| 생명보험 | H | 지급여력비율(K-ICS) |
| 손해보험 | I | 지급여력비율(K-ICS) |
| 증권 | F | 순자본비율 |
| 카드·캐피탈 | — | v1은 자동으로 받지 않고 '직접 확인'이에요 |

- 상장회사와 FISIS 금융회사 코드는 이름으로 맞춰요. 예를 들어 상장명 "KB금융"을 FISIS의 금융지주 이름과 맞춰요. 규칙은 빌더가 실제 목록을 보고 정하고, 맞추지 못하면 '직접 확인'이에요. 맞춘 결과는 저장해 둬요.
- 통계표 코드(`listNo`)와 계정 코드(`accountCd`)는 키가 있어야 확인돼요. KRX처럼 키가 오면 실제 응답을 녹화해서 확정해요. 그 전에는 이 기능을 꺼 둬요. 키가 없을 때와 똑같이 동작해요.

**키 신청**
- 비영리 용도는 신청하면 바로 나와요. 하루 1만 건까지 쓸 수 있어요.
- 신청서에 회사명과 사업자번호 칸이 있어서, 개인이 받을 수 있는지는 확실하지 않아요. 못 받아도 '직접 확인'으로 계속 쓸 수 있어요.
- 호출 수는 매주 금융회사 수십 곳마다 한두 건이라 넉넉해요.

### 3.5 기준값 (`settings.toml [financial]`)

```toml
[financial]
include = true              # 금융회사를 금융업 기준으로 분석해요. false면 지금처럼 빼요.
bank_cet1_min = 9.0         # 은행·금융지주 보통주자본비율 최소(%): 2026년 대형 은행지주(D-SIB) 최저 적립 필요 수준
insurer_kics_min = 130.0    # 보험 지급여력비율(K-ICS) 최소(%): 금융위원회 권고 기준 (2025-06-11 150%→130%)
securities_ncr_min = 100.0  # 증권 순자본비율 최소(%): 감독 최소 기준
```

- ROE 최소는 일반 기준(`criteria.roe_min`)을 같이 써요. 기준은 한 곳에 둔다는 계산기 원칙이에요. 금융업만 바꾸려면 업종 덮어쓰기를 써요. 예: `"64" = { roe_min = 7 }`.
- `[financial]` 값이 바뀌면 지금처럼 리포트 머리에 기준 변경 알림이 떠요.
- 공식 기준은 나중에 바뀔 수 있어요. 그래서 주석에 출처와 날짜를 남겨요.

### 3.6 리포트

- 종목 카드
  - 머리에 종류를 보여줘요. 예: "금융지주 · 금융업 기준으로 판정했어요".
  - 관문 ① 표에는 ROE, 적자 없음, 자본비율 줄이 있어요. 자본비율 줄에는 값, 기준, 기준월, 출처를 보여줘요. 해당 없는 세 줄은 '해당 없음'이에요.
  - 관문 ② 표의 잉여현금흐름 줄은 '해당 없음'이에요.
  - 5년 입력 숫자 표에서도 해당 없는 줄은 '해당 없음'이에요.
- 첫 페이지 관심 목록에서는 종목 이름 옆에 '금융' 표시를 해요.
- 제외 목록에는 '금융회사(그 밖)' 사유가 보여요.

### 3.7 엑셀 (`--excel`)

- 계산기는 그대로 써요. 해당 없는 칸(부채비율, 이자보상배율, 영업현금흐름, 설비투자)은 비워요.
- 그러면 엑셀에서는 그 항목이 '입력 필요'이고, 관문 ① 결과가 '확인 필요'로 보여요.
- B23 메모에 금융업 판정과 이유를 적어요. 예: "금융회사(금융지주)라 금융업 기준으로 판정했어요. 관문 ① 통과 (ROE 9.9%, 5년 적자 없음, 보통주자본비율 13.2% · 2026년 9월말), 관문 ② 통과. 부채비율·이자보상배율·현금흐름은 금융회사에 맞지 않아 비워 뒀어요."
- 그래서 금융회사만 엑셀 판정과 리포트 판정이 다를 수 있어요. 사용자가 2026-11-15에 동의했어요.

## 4. 경계 표시

- 관문 ①·② 항목에서 회사 숫자가 기준에서 '한 칸' 안쪽이면 '경계'로 표시해요. 통과한 쪽이든 탈락한 쪽이든 같아요.
- 판정은 그대로 두고, 표시만 해요.
- 비교는 계산기와 같은 반올림 기준으로 해요.

**한 칸 (기준 점검표와 같은 값)**

| 기준 | 한 칸 |
|---|---|
| ROE 최소 | 1%p |
| 부채비율 최대 | 25%p |
| 이자보상배율 최소 | 0.5배 |
| 영업현금흐름÷순이익 최소 | 0.1배 |
| 배당성향 하한·상한 | 5%p |
| 잉여현금흐름÷배당 최소 | 0.1배 |
| 보통주자본비율 최소 (금융) | 1%p |
| 지급여력비율 최소 (금융) | 10%p |
| 순자본비율 최소 (금융) | 100%p |
| 요구수익률 (점검표에서만) | 1%p |
| 안전마진 (점검표에서만) | 5%p |

**보여주는 곳**
- 종목 카드의 관문 표: 해당 줄에 '경계'와 기준까지의 차이를 보여줘요. 예: "ROE 7.6% · 기준까지 0.4%p".
- 첫 페이지 '아깝게 탈락' 목록에는 아래 두 조건을 모두 만족하는 종목만 올려요. 목록이 짧아서 첫 페이지에 둬요.
  - 경계 항목 때문에만 관문 ①·②에서 탈락했어요.
  - 그 항목이 통과였다면 관심 목록(매수선까지 20% 이내)에 들어왔을 종목이에요.
- 아슬아슬하게 통과한 종목은 카드에만 표시해요.

## 5. 기준 점검표

**보여주는 것**
- 이번 실행에서 분석한 종목 전체(빠른 탈락과 제외는 빼고)를 놓고, 기준마다 아래를 보여줘요.
  - 회사 숫자의 분포: 중간값, 25%·75% 지점, 종목 수
  - 지금 기준으로 통과하는 종목 수와 비율
  - 기준을 한 칸 엄하게 했을 때와 느슨하게 했을 때의 통과 수
  - 그때 관심 목록(매수선 이하·관심)에 새로 들어오거나 빠지는 종목 이름
- 대상 기준
  - 관문 ① 네 개, 금융회사는 자본비율
  - 관문 ② 세 개 (배당성향 하한·상한, 잉여현금흐름÷배당)
  - 요구수익률, 안전마진: 적정가와 매수선을 바꾸는 기준이라 관심 목록 변화만 보여줘요
- 금융회사와 일반 회사는 따로 보여줘요. 금융회사는 금융업 기준만 봐요.
- 업종 비교에 이미 있는 업종별 ROE 중간값도 같이 보여줘요.

**보여주는 방식**
- 새 페이지 `criteria.html`(기준 점검)에 둬요. 첫 페이지 머리의 '적용한 기준' 줄에서 링크해요.
- 시장 전체를 돈 실행에서 의미가 있어요. 호출 한도 때문에 일부만 받은 주에는 "일부만 분석해서 참고만 하세요" 알림을 달아요.

**계산**
- 실행할 때 파이썬에서 계산하고, 결과는 `data.js`에 들어가요. 기준마다 몇 줄이라 크기는 조금만 늘어요.
- 관문 기준은 그 항목만 다시 비교하면 돼요. 요구수익률과 안전마진은 적정가부터 다시 계산해요.
- 빌더가 속도를 재서 방법을 정해요. 목표는 전체 실행 시간이 1분 넘게 늘지 않는 거예요.

## 6. 사용자가 할 일

- (선택) FISIS 인증키를 신청해요.
  - fisis.fss.or.kr → OPEN API → 인증키 신청 (비영리)
  - 받으면 `keys.toml`의 `[fisis] auth_key`에 직접 넣어요. 채팅에는 붙여 넣지 않아요.
- 그 밖에 할 일은 없어요. KRX 키는 원래대로 기다려요.

## 7. 빌더에게 맡기는 것

- 카드·캐피탈 업종코드가 6491로 시작하는지 실제 자료로 확인
- FISIS 이름 맞추기 규칙, 통계표 코드, 계정 코드 (키가 생긴 뒤)
- 금융회사 카드와 기준 점검 페이지의 세부 모양과 문구
- 기준 점검표를 빠르게 계산하는 방법
- 테스트: 실제 DART 금융회사 응답 녹화(KB금융, 삼성화재, 삼성증권 등)와 합성 자료
- 원래 설계의 원칙은 그대로예요.
  - 빈칸은 0이 아니라 빈칸
  - 사용자에게 보이는 글은 한국어
  - 키는 출력하지 않음
  - 원본 계산기는 읽기만

## 8. Claude가 정한 것 (사용자가 확인할 것)

- 카드·캐피탈도 넣어요. 자본비율은 v1에서 '직접 확인'이에요.
- 금융회사의 ROE 최소는 일반 기준과 같은 값을 써요.
- 금융회사에 뜻이 없는 숫자는 리포트와 엑셀 모두에서 비워요.
- 자본비율 기본값은 공식 기준으로 해요. 보통주자본비율 9.0%(대형 은행지주 기준을 모든 은행에 적용), K-ICS 130%, 순자본비율 100%예요.
- '최근 5년 적자 없음' 항목을 더해요.
- 경계와 점검표의 '한 칸' 값은 4장의 표대로예요.
- 기준 점검표는 따로 페이지를 둬요.
- 9장의 세부 규칙 13개도 제가 정했어요.

## 9. 세부 규칙 (설계 검토 질문에 대한 답, Claude가 정한 것)

**금융회사 판정**
1. **최근 5년 적자 없음:** 순이익이 있는 해는 모두 0보다 커야 해요. 빈 해가 하나라도 있으면 '입력 필요'예요. 상장한 지 5년이 안 돼서 빈 해가 있는 회사도 같아요. 그래도 제외하지는 않아요. 관문 ① 결과는 많아야 '확인 필요'예요.
2. **자본비율과 연간 숫자를 섞어 써요.** 자본비율은 지금 버틸 힘이라 최신 분기 값을 써요. ROE와 적자 여부는 연간 사업보고서 값이에요.
3. **보험사:** 생명(6511), 손해(6512), 재보험(652) 모두 같은 지급여력비율 기준을 써요. FISIS에서 찾을 때는 생명(H)과 손해(I) 목록을 둘 다 봐요. 그래서 업종코드로 생명과 손해를 나눌 필요가 없어요.
4. **금융지주가 보험사를 가지고 있어도** 금융지주 자신의 보통주자본비율을 써요.
5. **지주회사인데 재무상태표를 받지 못하면** 금융지주인지 알 수 없어요. 이때는 일반 회사로 판정하지 않고, '받지 못한 종목'에 사유와 함께 올려요. 일반 기준으로 조용히 탈락하는 일을 막으려는 거예요.
6. **FISIS 이름 맞추기 결과**는 지금 쓰는 저장소(sqlite)에 저장해요. FISIS 금융회사 목록은 한 달에 한 번 새로 받아요.

**주간 기록과 알림**

7. **주간 기록(스냅샷)에 금융회사 종류와 자본비율(값, 기준월)을 같이 저장해요.** 아래 기능이 모두 같은 금융업 판정을 써야 하기 때문이에요.
   - 변화 원인 계산: 지난주 숫자로 판정을 다시 해요.
   - `--excel`: 주간 기록에서 숫자를 꺼내요.
   - 일부만 받은 주: 지난주에서 옮겨 둔 종목을 셀 때 판정을 다시 해요.
8. **`[financial]` 값도 기준 묶음에 넣어요.** 그래서 바뀌면 기준 변경 알림이 떠요.
   - 업그레이드 후 첫 실행에는 지난 기록에 이 묶음이 없어요. 이때는 항목마다 알림을 띄우지 않고 "금융회사를 금융업 기준으로 분석하기 시작했어요" 한 줄만 보여줘요.
   - 금융회사 기준값의 표시 단위는 %예요(예: 9% → 10%).
9. **업그레이드 후 첫 실행에서 관심 목록에 들어온 금융회사**는 지금 규칙대로 변화 원인이 '새로 분석됨'으로 보여요.

**경계 표시와 점검표**

10. **'아깝게 탈락' 목록의 조건:** 관문 ①·②에서 탈락한 항목이 모두 경계(한 칸 안쪽)여야 해요. 그 항목들을 통과로 바꿔 상태를 다시 판정했을 때 매수선 이하나 관심이 되는 종목만 올려요. 주가 자료가 없어서 상태를 정할 수 없는 종목은 올리지 않아요.
11. **점검표의 '한 칸 움직이면':** 그 기준 하나만 한 칸 바꾸고 다른 기준은 그대로 둬요. 그 상태로 모든 종목의 관문과 상태를 다시 판정해요.
    - 그래서 두 관문에서 탈락한 종목은 기준 하나만 움직여서는 새로 들어오지 않아요. 기준 하나의 실제 효과를 보여주려는 거예요.
    - 빠르게 계산하는 방법은 빌더가 정하되, 결과는 이 규칙으로 판정한 것과 같아야 해요.
    - '아깝게 탈락' 목록과는 따로 계산해요.

**테스트와 자료 모양**

12. **테스트**
    - 일반 회사의 엑셀·리포트 일치 테스트(예시 시트 비교)는 그대로예요.
    - 금융회사는 알고 있는 차이를 테스트로 고정해요. 엑셀 수식 계산에서는 관문 ①이 '확인 필요'이고, 리포트에서는 금융업 판정이 나와야 해요.
    - 엑셀 안에서 금융업 판정이 보이는 곳은 B23 메모뿐이에요. 지금 있는 '숫자 확인 필요' 사유는 지금처럼 메모에 이어 붙여요.
13. **`data.js`:** 새 항목을 더해도 돼요. `report.js`가 예전 자료와 새 자료를 구분해야 하면 `schema` 번호를 올려요.
